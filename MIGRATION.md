# Migrating from 1.x to 2.0

2.0 replaces the verification protocol and the client API of both packages. Verification now appraises one attestation document the enclave serves for a caller-chosen nonce (hardware quote, code and platform provenance, freshness and policy together), and no attested client serves a request that it has not verified for: the router and enclave clients verify before they exist, and the gateway client verifies a model's replica before its first request; `UnverifiedClient` from `tinfoil/unsafe`, which never verifies, is the development-only exception. Nothing from 1.x is aliased; the tables map each removed name to its replacement.

## `tinfoil`

| 1.x | 2.0 |
|---|---|
| `new TinfoilAI({ apiKey })`, lazy with `await client.ready()` | `await createClient({ apiKey })` from `tinfoil/openai` (install `openai` next to `tinfoil`): an `OpenAIClient` (an `OpenAI` subclass) over the discovered router, verified before it is returned. A browser page passes `bearerToken` instead of `apiKey`: an `apiKey` is refused outside Node and Bun, `dangerouslyAllowBrowser` or not, by the OpenAI client and the AI SDK provider alike. |
| `new SecureClient(options)` with `ready()`, `fetch`, `reset()`, `getBaseURL()`, `getEnclaveURL()` | `await RouterHTTPClient.create(options)` (the discovered router) or `await EnclaveHTTPClient.create(host, trust, options)` (one enclave), with `fetch` (absolute URLs), the `baseURL` and `enclave` properties, `ensureVerified()`, `reverify()`, `currentVerification()` and `lastVerificationAttempt()`; an enclave client also has `trust`. `new OpenAIClient(httpClient, { ...openaiOptions, apiPath? })` from `tinfoil/openai` wraps any of them, or a `GatewayHTTPClient`, as an OpenAI client, joining `apiPath` (`/v1/` by default) under the HTTP client's `baseURL`. |
| `enclaveURL` and `configRepo` options | `EnclaveHTTPClient.create(host, trust)`: the enclave is named up front, not chosen later. `trust` is `{ kind: "repoPin", repo }` for a GitHub repository, `{ kind: "projectPin", project, registryIDs? }` for a config registry project, `{ kind: "eitherPin", repo, project }` to accept either, or `signedBy`, `authorizedBy` or `embeddedConfig` for config trust of your own; a `configRepo` becomes `{ kind: "repoPin", repo: configRepo }` |
| `transport` option (default `"ehbp"` everywhere) | `transport: { kind: "tls" }` or `{ kind: "ehbp" }`, whose default depends on the platform: TLS on Node, Bun 1.4.0 or later and Deno 2.8.0 or later (the connection is pinned to the attested key), and EHBP in browsers and on a Bun older than 1.4.0 or a Deno older than 2.8.0. `{ kind: "tls" }` is a `ConfigurationError` where the platform can't pin the connection. Pass `transport: { kind: "ehbp" }` to keep sealed request bodies on Node. |
| `baseURL` as a proxy | `transport: { kind: "ehbp", proxyURL }`; it must be HTTPS (`http://` only to localhost or a loopback IP address), without user information, a query or a fragment, and not on the enclave's own origin, and requests carry `X-Tinfoil-Enclave-Url`. Its path is where the proxy is mounted: an `OpenAIClient` appends its `apiPath` (`/v1/` by default) |
| `fetch` option on `SecureClient` (the network implementation that carries EHBP requests) | `transport: { kind: "ehbp", fetch }` on `RouterHTTPClient.create` / `EnclaveHTTPClient.create` (`GatewayHTTPClient.create` takes it as its `fetch` option), with the same semantics: it receives requests with their bodies sealed, the client opens the responses, and attestation documents keep the runtime's fetch |
| `createTinfoilAI(apiKey, options)` from `tinfoil` | `await createTinfoil({ apiKey \| bearerToken, ...clientOptions, enclave? })` from `tinfoil/ai-sdk`, its own entry so the AI SDK stays out of bundles that don't use it; `provider.httpClient` is the attested client underneath |
| `@ai-sdk/openai-compatible` installed with `tinfoil` as a dependency (also in 2.0.0-rc.1) | an optional peer dependency, like `ai`: install both next to `tinfoil` to use `tinfoil/ai-sdk` (`npm install tinfoil@next ai @ai-sdk/openai-compatible`). The root entry, `tinfoil/openai` and `tinfoil/unsafe` don't import either, so `npm install tinfoil@next` is enough for them. Without it, importing `tinfoil/ai-sdk` fails with a module-not-found error that names `@ai-sdk/openai-compatible`. |
| `TINFOIL_API_KEY` read when `apiKey` was omitted | no environment defaults: pass the credential |
| `attestationBundleURL`, `fetchAttestationBundle`, `fetchRouter` | the document comes from the enclave, and router discovery is built into the router clients (the first router that verifies, falling back to `inference.tinfoil.sh`). To fetch documents and the router list through your own origin instead, as `attestationBundleURL` did, pass `fetchAttestation: attestationRelay(url)` and `fetchRouterList: routerListRelay(url)`, or functions of your own; see the README's section on a page that contacts only your own origin |
| `getVerificationDocument()`, `VerificationDocument`, `VerificationStepState` | `ensureVerified()` returns a currently valid `VerificationReport`, whose `steps` show each layer and whose `verifiedFacts` hold every fact, verifying again if needed; `currentVerification()` returns the report of the verification that requests are bound to now, without network I/O; `lastVerificationAttempt()` returns the most recent attempt, `{ report }` or `{ error }`, unchecked, and the `onVerificationAttempt` option reports every attempt. A gateway client's `ensureVerified(model)` returns the report of a replica serving the model, its `reverify(model)` verifies that replica again, and its `replicas()` returns one entry for each replica that it has tried, with that replica's current verification and last attempt. A verification failure is an `AttestationError` wrapping a `VerificationError` whose `layer` names the failed check and whose `report` shows the failed step and the partial facts |
| `Verifier`, `assembleAttestationBundle` and the attestation types re-exported from `tinfoil` | import the verifier from `@tinfoilsh/verifier`; to change the policy, pass the client's `policy` option, the same plain data that `Verifier.create` takes as its second argument |
| `FetchError` | `NetworkError`. `TinfoilError`, `ConfigurationError` and `AttestationError` keep their names. |
| a verification failure thrown by `await client.ready()`, or by the first request as an `APIConnectionError` wrapping it | the factory rejects with the error itself. A request through the OpenAI API surface whose enclave fails to verify again rejects with `APIConnectionError` with the error as `cause`, after the OpenAI client's `maxRetries` retries (2 by default) |
| `client.realtime({ model, options })` | `await createRealtimeWebSocket(client, { model, wsOptions })` from `tinfoil/openai` (Node only) |
| `secureClient.createWebSocket(path, options)`, `getPinnedWebSocketOptions()` | `await createWebSocket(client, path, options)`, `await pinnedWebSocketOptions(client)` |
| `new UnverifiedClient()` from `tinfoil/unsafe`, discovering a router | `await UnverifiedClient.create({ baseURL \| keyOrigin })` from `tinfoil/unsafe`: it never discovers a server, and is for development against a local server only |
| `createUnverifiedEncryptedBodyFetch` | removed: `UnverifiedClient.fetch` |
| a relative request URL passed to a client's `fetch` | every client's `fetch` takes an absolute URL; `client.baseURL` (always slash-terminated) is the base to resolve a path against, `new URL(path, client.baseURL)` |
| `tinfoil/v3`, `tinfoil/v3/ai-sdk`, `tinfoil/v3/unsafe` (pre-release entries) | `tinfoil`, `tinfoil/ai-sdk`, `tinfoil/unsafe` |
| the router's user cache secret resolved from the `TINFOIL_USER_CACHE_SECRET` environment variable, then a secret persisted at `~/.tinfoil/user_cache_secret` | neither is read: without a non-empty `userCacheSecret` option or a non-empty per-request `user_cache_secret`, each process (or browser page) uses a random secret that is generated in memory, so prompt-cache hits are no longer shared across processes. An empty value counts as unset: an empty option falls back to that generated secret, and an empty body field is replaced. Pass a non-empty `userCacheSecret` to keep a secret that is stable across processes or machines. |

Unchanged: the router client's `userCacheSecret` and the per-request `user_cache_secret` field (the field still overrides the option), the session recovery helpers (`sessionRecoveryToken(response)` replaces reading the token off a response). The OpenAI types and errors are re-exported from `tinfoil/openai`. An enclave client never adds a `user_cache_secret`: a caller that points one at Tinfoil's router sets it in each request body.

## From a 2.0 release candidate

2.0.0-rc.4 and earlier configured the clients with combined options that were checked against each other. Each setting that only makes sense with others is now one value with variants, told apart by `kind`, so a combination that would be invalid can't be written.

| 2.0.0-rc.4 | 2.0 |
|---|---|
| `EnclaveHTTPClient.create(host, { repo })`, `{ project }`, `{ repo, project }` | `EnclaveHTTPClient.create(host, { kind: "repoPin", repo })`, `{ kind: "projectPin", project }`, `{ kind: "eitherPin", repo, project }` |
| an empty pin with a `verifier` whose `configAuthorizer` or embedded config authorizes the config | `{ kind: "authorizedBy", authorize }` or `{ kind: "embeddedConfig", bytes, name? }` as the trust argument |
| `verifier: await Verifier.create({ configRegistryIDs })` with a `{ project }` pin | `{ kind: "projectPin", project, registryIDs }`; an empty list is a `ConfigurationError` |
| `verifier: await Verifier.create({ configSigningKeys })` | `{ kind: "signedBy", keys, project? }` |
| `verifier: await Verifier.create({ pinnedRegisters, freshnessMaxAgeMs, freshnessSigningKeys, embeddedReferences })` | `policy: { pinnedRegisters, freshnessMaxAgeMs, artifacts }`, on the enclave, router and gateway options; `ModelPin.verifier` becomes `ModelPin.policy` |
| `client.pin` | `client.trust` on an enclave client, a copy of the trust argument; the router client has none |
| `pinnedModelsOnly: true` on the gateway options | removed: a gateway client always serves only the models that `modelPins` names, so `modelPins` is required and needs at least one pin |
| a gateway request for a model without a pin, whose replicas were verified against the repository that the catalog named | pin every model that you request, for example `modelPins: new Map([[model, { repo: "tinfoilsh/<name>" }]])`; a request for an unpinned model is now a `ConfigurationError`. The gateway's `policy` now applies only to the pins that set none |
| `transportMode: "tls"` | `transport: { kind: "tls" }`, or unset on Node, Bun 1.4.0 or later and Deno 2.8.0 or later, where TLS is the default; it is refused where the platform can't pin the connection (browsers, older Bun and Deno) |
| `transportMode: "ehbp"`, with a proxy `baseURL` and a `fetch` | `transport: { kind: "ehbp", proxyURL, fetch }`. A `baseURL` that was a path on the enclave's own origin is no longer supported, and a proxy on that origin is a `ConfigurationError` |
| `TransportMode` | `Transport`, `TLS` and `EHBP` |
| the router list, always fetched from Tinfoil and tried in its order | `fetchRouterList` chooses where it comes from (`routerListRelay(url)` for a relay), and discovery shuffles a copy of the list before it tries the routers |
| `tinfoil/http` | `tinfoil`: the root entry imports neither the OpenAI client nor the AI SDK, so the subpath is removed |
| `createClient`, `TinfoilClient`, `OpenAIOptions` and the OpenAI errors from `tinfoil` | `createClient`, `OpenAIClient`, `OpenAIClientOptions` and the OpenAI errors from `tinfoil/openai`, with `openai` installed next to `tinfoil` |
| `EnclaveOpenAIClient.create(host, pin, options, openaiOptions)` | `new OpenAIClient(await EnclaveHTTPClient.create(host, trust, options), openaiOptions)` |
| `RouterOpenAIClient.create(options, openaiOptions)`, `GatewayOpenAIClient.create(options, openaiOptions)` | `new OpenAIClient(await RouterHTTPClient.create(options), openaiOptions)`, and likewise with `GatewayHTTPClient` |
| an OpenAI client over a proxy `baseURL: "https://proxy.example/v1/"` | `proxyURL: "https://proxy.example/"`: the OpenAI client appends `/v1/`, or the `apiPath` among the options of `new OpenAIClient` |
| a gateway `url` that ends with the API path, such as the old default `https://inference-gateway.tinfoil.sh/v1/`, a gateway client's `baseURL` ending in `/v1/`, and an `apiPath` refused with a gateway client | the gateway's origin, or the URL that it is mounted under, such as the new default `https://inference-gateway.tinfoil.sh/`: an `OpenAIClient` joins its `apiPath` (`/v1/` by default) under it, as under an EHBP `proxyURL`, so `apiPath` now works with a gateway client. A `url` with a path names a mount: the catalog and the attestation relay are fetched under it (`https://gateway.example/mount/catalog`), not from the host's root. Requests reach the same endpoints as before with the default gateway; code that builds request URLs from a gateway client's `baseURL` joins `v1/` under it |
| `new OpenAIClient(httpClient, { apiPath }, openaiOptions)`, with `OpenAIOptions` as a separate argument | `new OpenAIClient(httpClient, { ...openaiOptions, apiPath })`: `apiPath` moves into the one options object, and the client takes it out before the rest reach openai-node. `OpenAIOptions` is removed, `OpenAIClientOptions` carries `apiPath`, and `createClient({ apiKey, apiPath })` and `withOptions({ apiPath })` take it too. A call with three arguments is a `ConfigurationError` |
| an empty `apiPath`, which selected `/v1/` (on the OpenAI client and the AI SDK provider) | leave `apiPath` out: an empty path is now a `ConfigurationError` |
| `dataResidency` among the OpenAI options, refused | ignored, as are `baseURL` and `OPENAI_BASE_URL`: the client sets the base URL itself |
| `createRealtimeWebSocket` from `tinfoil` | `createRealtimeWebSocket` from `tinfoil/openai` |
| `wsOptions.headers` on `createWebSocket`, silently dropped (and likewise `origin`, `protocol`, `finishRequest` and the settings that choose the peer or check its certificate) | the top-level `headers` option (an `Origin` or `Authorization` header goes there too) and `protocols` for subprotocols; a reserved key in `wsOptions` that is set to a value other than `undefined` is now a `ConfigurationError` (`auth`, which `ws` turns into an `Authorization` header, is now reserved too), as is a non-empty `wsOptions` on Bun, where they were ignored |
| `userCacheSecret` on an enclave client, or on the AI SDK provider with `enclave` | removed: an enclave client never adds a `user_cache_secret`; set it in each request body |
| `createTinfoil({ enclave: { host, repo, project }, transportMode, baseURL, fetch, verifier })` | `createTinfoil({ enclave: { host, trust }, transport, policy, apiPath? })` |
| `Verifier.create({ ...options })`, `VerifierOptions`, `EmbeddedReferences`, `Verifier.callerAuthorizesConfig` | `Verifier.create(config?, policy?)`, as described under `@tinfoilsh/verifier` below; `callerAuthorizesConfig` is removed |
| an `onVerification` callback taking `(host, report, error)`, with `report` and `error` each possibly undefined | `onVerificationAttempt: (host, attempt) => …`, where `attempt` is the same `VerificationAttempt` that `lastVerificationAttempt()` returns: `{ report }` for a verification that passed or `{ error }` for one that failed, so that checking one narrows the other. A callback that declares `(host, report, error)` no longer type-checks; read `attempt.report` and `attempt.error` instead |
| `lastVerification()` and the `onVerification` option of the enclave, router and gateway clients, and the `OnVerification` type | `lastVerificationAttempt()`, `onVerificationAttempt` and `OnVerificationAttempt`, with the same shape and semantics: the names say that they describe attempts, failed ones included. The new `currentVerification()` of the enclave and router clients returns, without network I/O, the report of the verification that requests are bound to now, or `undefined` before the first success, after an `AttestationError` or a key rejection discarded it, and once it has expired |
| a gateway client's `lastVerification()`, whose entries spread the replica's last attempt (`report` or `error`) into the entry | `replicas()`, whose entries hold that attempt as `lastAttempt` (`{ report }` or `{ error }`) next to `current`, the replica's verification that requests are bound to now, or `undefined`. A gateway client also has `reverify(model)`, which verifies again the replica that `ensureVerified(model)` would return |
| `VerificationError` imported from `@tinfoilsh/verifier`, to inspect an `AttestationError`'s `cause` | `VerificationError` from `tinfoil`, with `REPORT_SCHEMA_VERSION` and the report types (`VerificationReport`, `VerifiedFacts`, `Step`, the `*JSON` types and the rest); drop a direct `@tinfoilsh/verifier` dependency that was only for them, since one whose version differs from the one that `tinfoil` pins installs a second copy, whose `VerificationError` fails `instanceof` on the errors that a client throws |
| `report.toJSON()` and `verifiedFacts.toJSON()` with camelCase members, `measured.cpu.measurement`, every step's `message` and ISO 8601 times | the JSON form that every Tinfoil SDK exports: snake_case members (`verified_facts`, `partial_facts`, `config_repo`, `signing_key_hint`, `registry_id`, …), `schema_version: 1`, `measured.cpu_measurement`, a `message` only for a failed or skipped step, no `""` members, no code measurement when the release fixes no register, and RFC 3339 times in UTC. The report's own properties are unchanged, and the `*JSON` types describe the new form |

## `@tinfoilsh/verifier`

| 1.x | 2.0 |
|---|---|
| `new Verifier({ serverURL, configRepo })`, `verify()`, `verifyBundle(bundle)` | `await Verifier.create(config?, policy?)`, then `verifyV3(document, nonce, pin)` or `verifyV3At(document, nonce, pin, when)`, where `pin` is `{ repo }`, `{ project }` or both. Fetching is the caller's job: `GET https://<host>/.well-known/tinfoil-attestation?nonce=<hex>` with a `randomNonce()`. |
| `verifyAttestation`, `assembleAttestationBundle`, `AttestationBundle`, `AttestationDocument`, `AttestationResponse` | removed: the collateral travels inside the document |
| `verifyCertificate`, `CertVerificationResult` (HPKE key and attestation hash in certificate SANs) | removed: channel keys are endorsed in the document's crypto material, read from the `tlsPublicKeyFP`, `hpkePublicKey` and `cryptoMaterial` properties of a report's `verifiedFacts` or with `cryptoMaterialData(id, format)` |
| `compareMeasurements`, `measurementFingerprint`, `hashAttestationDocument`, `PredicateType`, `AttestationMeasurement`, `HardwareMeasurement` | the `Measurement` and `Expected` types with `parseRegister`, `parseExpectedSevSnp`, `parseExpectedTdx`, `registerHex` and `formatMeasurement`; the `codeMeasurement` and `enclaveMeasurement` properties of `VerifiedFacts`; `pinnedRegisters` on the verifier to require registers |
| `getVerificationDocument()`, `VerificationDocument`, `VerificationStepState`, `cloneVerificationDocument`, `VERIFICATION_DOCUMENT_SCHEMA_VERSION` | `VerificationReport`: `verifyV3` returns one with its `steps` and `verifiedFacts`, and a `VerificationError` carries its `layer` and a `report` with the failed step and the `partialFacts` |
| `TinfoilError`, `ConfigurationError`, `FetchError`, `AttestationError` | `VerifyError` with `UsageError` (invalid inputs) and `VerificationError` (the document must not be trusted); the `tinfoil` package keeps its own error classes |
| `VERIFIER_NAME`, `VERIFIER_VERSION` | `report.metadata.verifier.name` and `report.metadata.verifier.version` |
| `@tinfoilsh/verifier/v3` (pre-release entry) | the package root |

`Verifier.create(config?, policy?)` is new in 2.0, and each trust choice is one value told apart by `kind`. `config` is the config trust: undefined for the public registry, `{ kind: "registries", ids }` for exactly these registries (list `PUBLIC_REGISTRY_ID` among them to keep the public one, `[PUBLIC_REGISTRY_ID, ...mine]`), `{ kind: "configSigningKeys", keys }`, `{ kind: "configAuthorizer", authorize }`, or an exact config as `{ kind: "embeddedConfig", bytes, name? }` or, when the bytes are not disclosed, `{ kind: "embeddedConfigReference", digest, runtime, name? }`. `policy` is plain data: `pinnedRegisters`, `freshnessMaxAgeMs` and `artifacts`, `{ kind: "endorsedArtifacts", freshnessKeys? }` or `{ kind: "embeddedArtifacts", runtime?, platform?, freshnessKeys? }`.
